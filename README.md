# АГАТУ КТиУ — расписание через интернет

Веб-приложение доступно с телефона и компьютера по ссылке [ktiu.onrender.com](https://ktiu.onrender.com/). Просмотр расписания и PDF доступен всем, а одна кнопка обновления защищена паролем владельца.

Код уже размещён в GitHub и развёрнут на Render. Чтобы изменения появились на сайте, обновите репозиторий и дождитесь нового развёртывания. Пароль владельца уже задан в переменной среды Render; архив его не содержит.

## Как обновить существующий сайт

1. Распакуйте весь ZIP. В папке `AGATU_KTiU_Web` видны `Dockerfile`, `server.mjs`, `package.json`, `data`, `lib`, `public` и `vendor`.
2. Откройте существующий [репозиторий baibalexson-web/ktiu](https://github.com/baibalexson-web/ktiu) и замените файлы содержимым распакованной папки. Сохраните через **Commit changes**. Файлы должны находиться **в корне репозитория**, а не во вложенной папке: `server.mjs` и `vendor/pdfjs/pdf.mjs` должны открываться по этим путям. Загрузите `vendor` целиком. Если вы обновляете репозиторий через Git на своём компьютере: `git add .`, `git commit -m "Обновить веб-расписание до 1.3"`, `git push`. Не загружайте только ZIP вместо исходников.
3. Дождитесь автоматического Deploy в [Render](https://dashboard.render.com/). Если он отключён, откройте свой Web Service и выберите **Manual Deploy → Deploy latest commit**. Новый сервис создавать не требуется. В журнале не должно быть ошибки `Cannot find module '/app/vendor/pdfjs/pdf.mjs'`.
4. Убедитесь, что в Render → **Environment** сохранён `ADMIN_TOKEN` длиной не менее 16 символов. **Не записывайте пароль в GitHub.** `PUBLIC_MODE=1` и `AGATU_CACHE_DIR=/var/data/agatu` указаны в Dockerfile.
5. Откройте [сайт](https://ktiu.onrender.com/) и обновите вкладку. На странице должна быть надпись **«Версия 1.3»** и одна кнопка **«Обновить расписание»**. Если по-прежнему две кнопки, проверьте commit, журнал Deploy и перезагрузите страницу.
6. Нажмите **«Обновить расписание»**, введите пароль владельца и дождитесь загрузки и проверки. Откройте отчёт, особенно если есть предупреждения. Посетителям пароль не нужен; вкладка хранит его только в оперативной памяти до перезагрузки.

На бесплатном плане Render обновлённые PDF могут пропасть после остановки или перезапуска сервиса; тогда снова откроется встроенная копия и понадобится нажать кнопку обновления. Для постоянного хранения нужен совместимый платный план с **Persistent Disk** в точке `/var/data`: https://render.com/docs/disks . В настройке **Health Check Path** можно указать `/api/health`.

## Ссылка на вашем существующем сайте

Добавьте кнопку «Расписание преподавателей» и вставьте полученный адрес `https://…onrender.com`. В Google Сайтах это делается в редакторе через **Вставка → Кнопка → Ссылка → Опубликовать**: https://support.google.com/sites/answer/90538 . Приложение откроется отдельной страницей с полноценным интерфейсом. Для встраивания интерфейса внутрь рамки другого сайта потребуется отдельная настройка разрешённых доменов; эта сборка настроена для открытия по ссылке.

Не загружайте `index.html` в Google Сайты как отдельный файл: кнопки обновления обращаются к запущенному серверу JavaScript. Публичный адрес предоставляется хостингом, а Google Сайт ведёт к нему.

## Как работает обновление

- **Обновить расписание** — находит текущие семь ссылок в разделе КТиУ → Очно на официальной странице АГАТУ, скачивает все PDF, проверяет SHA-256 и показывает распознанные занятия. Пока идёт работа, старое расписание остаётся на экране.
- Если в одной записи отсутствует время, она пропускается, а остальные занятия показываются. Предупреждение указывает страницу и источник. Если целая страница или один источник не распознаны, показываются записи из остальных. **Результат с предупреждениями может быть неполным:** сверьте нужные занятия с оригинальным PDF. При неудаче скачивания одного PDF или отсутствии всех распознанных занятий сохраняется прежнее расписание.
- Источники и время получения можно посмотреть в интерфейсе. Если внутренняя версия PDF изменилась при прежней ссылке, скачивание получит новые байты и сохранит новый SHA-256.
- Данные от 05.10.2026 включены как исходная копия. Не считайте её расписанием текущей недели; обновите документы после развёртывания.
- Длинный субботний блок Федорова П.И. сохраняется одной карточкой, а счётчик учитывает две пары по интервалам из того же PDF.

Доступ к кнопке обновления защищён `ADMIN_TOKEN`. Посетители могут открывать расписание, локальные PDF, отчёт, CSV и календарь. Пароль задаётся только в Render. Если потеряли его, замените значение переменной в настройках сервиса и перезапустите размещение.

## Что входит в архив

| Файл / папка | Назначение |
|---|---|
| `Dockerfile`, `.dockerignore` | Собирают сервер Node.js для интернет-хостинга без установки npm-пакетов в работающий контейнер. |
| `server.mjs` | Публичный HTTP API, проверка пароля, чтение активного набора, раздача интерфейса и PDF. |
| `lib/` | Поиск очных источников, скачивание, разбор таблиц и сохранение целых наборов. |
| `public/` | Адаптивный интерфейс, поиск преподавателей, фильтры, выгрузки и окно пароля. |
| `data/` | Встроенная копия семи PDF и их SHA-256 от 05.10.2026. |
| `vendor/` | PDF.js и шрифты: читают PDF целиком на JavaScript. |
| `package.json`, `package-lock.json` | Версия Node.js, команды и тестовые зависимости; обычная работа не требует установки npm-пакетов. |
| `tests/` | Автоматические проверки, в том числе защита обновлений в публичном режиме. |
| `reports/tests_web.txt` | Итоговый вывод автоматических тестов публичной сборки. |
| `README_LOCAL.md`, Windows `.bat` | Инструкция и запуск того же приложения на одном компьютере без хостинга. Для локального режима не задавайте `PUBLIC_MODE=1`. |
| `THIRD_PARTY_NOTICES.md` | Лицензии сторонних компонентов. |

Для разработчика локальный запуск: `node server.mjs --open`. Публичный запуск без Docker: установите Node.js ≥24.5, задайте `PUBLIC_MODE=1`, `ADMIN_TOKEN`, `AGATU_CACHE_DIR` и `PORT`, затем выполните `node server.mjs`. Сервер слушает `0.0.0.0:PORT`, а HTTPS обеспечивает внешний хостинг. Не открывайте этот порт напрямую без HTTPS-прокси.

## Ограничения

Доступность сайта и хранение обновлённых PDF зависят от тарифного плана хостинга. На бесплатном Render служба может засыпать, первый заход после простоя будет медленнее, а сохранённые данные исчезнут при остановке. Платный план с диском сохраняет PDF после перезапуска. Изменение формата официальных PDF может потребовать обновления парсера. При ошибках распознавания отдельные занятия могут быть пропущены: смотрите предупреждения и сверяйтесь с PDF.
